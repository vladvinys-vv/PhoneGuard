# Room Schema History

This directory contains exported Room database schemas (`<version>.json` for every
`@Database` version). They are **generated by kapt** during the build
(`room.schemaLocation` in `app/build.gradle`) and **must be committed** — they are the
input for migration tests.

## Why they are needed

`AppDatabaseMigrationTest` (androidTest) uses `MigrationTestHelper`, which reads the
schema of version *N* from the **androidTest assets**:

```groovy
sourceSets {
    androidTest.assets.srcDirs += files("$projectDir/schemas")
}
```

Without that line the test fails with
`IllegalStateException: Cannot find the schema file in the assets folder`.

`runMigrationsAndValidate(...)` also validates that the migration produces exactly the
schema Room expects, which is why a mismatch between an `ALTER TABLE` and the entity is
caught on CI instead of on a user's phone after an update.

`tools/static_audit.py` additionally checks migrations against `@Entity` definitions
statically (`check_migrations_match_entities`), so drift is visible even without a device.

## Refreshing the schemas

```bash
./gradlew :app:kspDebugKotlin   # or any task that compiles room-compiler, e.g. assembleDebug
git add app/schemas
```

Bump `@Database(version = …)` together with a new `Migration` object and commit the new
schema file in the same change.
