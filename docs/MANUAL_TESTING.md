# Ручное тестирование

Сценарии, которые нельзя закрыть юнит-тестами: реальные разрешения, службы, системные диалоги и OEM-прошивки.
Минимальный набор устройств: API 26 (Android 8), 29, 31, 33, 34, 35 — плюс хотя бы один Samsung/Xiaomi/Huawei
(у них агрессивное убийство фоновых служб).

## 1. Онбординг и разрешения

- [ ] На первом запуске показывается онбординг, после него — дашборд.
- [ ] Камера, SMS, телефон, геолокация, уведомления запрашиваются с пояснением, зачем.
- [ ] Отказ в разрешении не роняет приложение: соответствующий экран показывает «нет доступа» и как его выдать.
- [ ] На Android 13+ без `POST_NOTIFICATIONS` блокировки работают, но без уведомлений.
- [ ] Отказ один раз: у пункта появляется «Отказано — можно спросить ещё раз», повторное нажатие
      снова показывает системный диалог.
- [ ] Отказ «больше не спрашивать» (Android 11+: второй отказ): пункт пишет «Отключено в
      системе», рядом кнопка «Открыть настройки приложения», а «Принять и продолжить» **активна** —
      онбординг не превращается в тупик.
- [ ] Выдача разрешения в системных настройках и возврат в приложение: галочка обновилась без
      перезапуска экрана.
- [ ] Уже выданный пункт не переключается (галочка неактивна): отозвать разрешение из приложения
      нельзя, и снятая галочка была бы ложью.

## 2. Блокировка звонков

- [ ] Номер из чёрного списка не звонит (журнал: запись `isSms = false`).
- [ ] Номер из белого списка проходит, даже если он же есть в спам-базе.
- [ ] Номер в другом формате (`0170…` и `+49 170…`) матчится — проверка нормализации.
- [ ] Скрытый номер блокируется при включённом «блокировать скрытые».
- [ ] Уведомление о блокировке приходит, номер в нём замаскирован.
- [ ] CSV-импорт добавляет номера и не пускает мусор.
- [ ] В журнале блокировок видна причина («спам-база», «чёрный список», «скрытый номер»).
- [ ] «Сформировать жалобу» при пустом журнале: сообщение «нет подходящих звонков», файлов нет.
- [ ] Без доверенного номера: сообщение «укажите номер», файлов нет.
- [ ] С заблокированным спам-звонком: файлы `exports/bnetza_beschwerde_*.txt|.csv` появляются,
      в CSV — `Ja/Nein`, точка с запятой в названии фирмы не ломает строку.
- [ ] Иностранный номер, заблокированный настройкой «международные», в жалобу **не** попадает.

## 3. Фильтр SMS

- [ ] Спам-сообщение, разбитое на две части, блокируется целиком: ссылка может быть во второй части.
- [ ] Сообщение с ссылкой и «давящим» словом («срочно», «заблокирован», «подтвердите») попадает
      в находки полного скана, но **не** съедается: доставку отменяет только блокировка по номеру.
- [ ] Обычное сообщение со ссылкой без таких слов находкой не становится.
- [ ] SMS с номера из чёрного списка: запись в журнале, уведомление «SMS заблокировано».
- [ ] Номер из белого списка проходит, даже если он есть в спам-базе.
- [ ] Длинное (многочастное) SMS от одного отправителя даёт **одну** запись в журнале.
- [ ] Текст «ссылка + давящие слова» от неизвестного номера даёт «Подозрительное SMS».
- [ ] Если PhoneGuard **не** приложение SMS по умолчанию, сообщение всё равно приходит в системное
      приложение, а PhoneGuard только предупреждает (это ожидаемое поведение, а не баг).
- [ ] Если PhoneGuard назначено приложением SMS по умолчанию, блокировка по номеру отменяет доставку.
- [ ] Анти-воровские команды (`LOCK`, `WIPE`, …) продолжают работать — фильтр не перехватывает их раньше.

## 4. Брандмауэр (VPN)

- [ ] Включение VPN показывает постоянное уведомление, выключение — убирает его.
- [ ] Приложение с правилом «блокировать всё» теряет сеть, остальные приложения работают.
- [ ] Правило «только Wi-Fi» переключается при переходе на мобильную сеть (туннель пересоздаётся).
- [ ] IPv6-трафик заблокированного приложения тоже не проходит.
- [ ] Журнал блокировок пополняется, но не чаще ~10 записей в секунду.
- [ ] После отзыва VPN-разрешения в системных настройках сервис корректно останавливается.

## 5. Полное сканирование

- [ ] Проходят все 16 шагов, прогресс переводится и не «зависает» на последнем шаге.
- [ ] Повторный запуск во время скана не запускает второй (шаг `ALREADY_RUNNING`).
- [ ] Отмена скана не оставляет включённый индикатор.
- [ ] Отчёт сохраняется в историю, сравнение с предыдущим показывает разницу.
- [ ] PDF-экспорт создаёт файл, которым можно поделиться.
- [ ] На устройстве без root все проверки дают осмысленные результаты (нет ложных «критично»).

## 6. Чек всего телефона

- [ ] Экран открывается с дашборда и из настроек.
- [ ] Оценка 0..100 соответствует состоянию устройства (блокировка экрана, шифрование, патч, ADB).
- [ ] Результат сохраняется: после перезапуска дашборд показывает его без нового аудита.
- [ ] На устройствах с ограниченным профилем аудит не падает.

## 7. Сейф

- [ ] Разблокировка по биометрии и по PIN.
- [ ] Импорт изображения/видео/документа, лимит 50 МБ срабатывает.
- [ ] Предпросмотр открывает файл во внешнем приложении, копия остаётся в кеше и удаляется при следующем предпросмотре.
- [ ] `FLAG_SECURE`: скриншот и запись экрана блокируются.
- [ ] Удаление файла требует подтверждения.
- [ ] «Экспорт сейфа» с фразой короче 8 символов: кнопка неактивна, при вводе видно «минимум 8 символов».
- [ ] Повтор фразы не совпал — экспорт не запускается.
- [ ] Успешный экспорт: сообщение с путём `exports/phoneguard_vault_*.pgvault`, файл существует,
      и в нём **нет** читаемых имён файлов (`strings`/`grep` по архиву их не находит).
- [ ] Импорт того же архива на другом устройстве (или после очистки данных): файлы вернулись,
      имена, размеры и категории сохранились.
- [ ] Импорт с неверной фразой: «неверная парольная фраза или архив повреждён», в сейфе
      ничего не появилось (недописанные файлы не остались).
- [ ] Импорт чужого файла (журнал, картинка): «это не архив сейфа PhoneGuard».
- [ ] Повторный импорт того же архива не перезаписывает файлы, а добавляет копии с суффиксом.
- [ ] Перенос между устройствами целиком: экспорт → `adb pull` архива → установка на второе
      устройство → импорт → число элементов, имена, размеры и категории совпадают; превью
      открывается, файл на месте (см. 13.2).

## 8. Анти-вор

- [ ] PIN задаётся и проверяется, после N неудач — блокировка.
- [ ] Замена SIM обнаруживается (`SimSwapReceiver`). При закрытом приложении приходит
      уведомление «Вы поменяли SIM?» (канал «Смена SIM-карты», id 4101), тап по нему открывает
      экран подтверждения — в том числе поверх блокировки экрана.
- [ ] «Да» — событие помечается подтверждённым, уведомление исчезает, устройство не блокируется.
- [ ] «Нет» — включается lost mode, координаты уходят доверенным контактам, устройство блокируется
      (при активном Device Admin).
- [ ] Тревога по SMS играет и останавливается кнопкой (в том числе из уведомления).
- [ ] Координаты уходят на доверенный номер; без разрешения `SEND_SMS` — ничего не отправляется.
- [ ] Команды `WIPE`/`LOCK` работают только там, где это разрешено (device owner / device admin),
      в остальных случаях пользователь видит понятное сообщение.

### 8.1. Удалённые SMS-команды `#PG:PIN:КОМАНДА`

Отправлять с другого телефона на свой номер. Разбор проверен юнит-тестами
(`SmsRemoteCommandTest`), здесь — то, что видно только на устройстве.

- [ ] Все шесть команд выполняются: `LOCK` (блокировка экрана), `ALARM` (сирена, останавливается
      кнопкой), `LOCATION` (координаты на номер отправителя), `WIPE` (стирание при активном Device
      Admin), `PHOTO` (снимок камерой), `STATUS` (состояние батареи/SIM/сети ответным SMS).
- [ ] Регистр не важен: `#pg:1234:lock` и `#PG:1234:LOCK` работают одинаково.
- [ ] Многочастное SMS (длинная команда, разбитая оператором на части) выполняется **один раз**.
- [ ] Неверный PIN: команда не выполняется, приходит локальное уведомление о попытке.
- [ ] Пять неверных PIN подряд → ввод PIN отклоняется 15 минут; **перезагрузка телефона блокировку
      не снимает** (состояние в DataStore), успешный PIN её сбрасывает.
- [ ] Неизвестная команда (`#PG:1234:HACK`) ничего не делает.

### 8.2. Приманки honeypot

- [ ] После инцидента с высоким риском в `files/phoneguard_honeypot` появляются файлы
      `<время>_passwords.txt`, `<время>_wallet_backup.json`, `<время>_private_photos`, а их
      содержимое похоже на настоящую находку (в нём **нет** слова `honeypot`).
- [ ] После пяти инцидентов в каталоге остаётся ровно **три** набора файлов (старые удаляются).
- [ ] Посторонние файлы, положенные в этот каталог вручную, не удаляются.
- [ ] Открытие приманки (например, `adb shell cat <путь>`) даёт событие инцидента; повторное
      открытие того же файла в течение 10 минут событие **не** дублирует.
- [ ] Детектор подглядывания запускается с разрешением камеры и не падает без него.

## 9. Настройки и приватность

- [ ] Переключение языка применяется сразу и сохраняется после перезапуска.
- [ ] Тёмная тема следует системе и ручному переключателю.
- [ ] Экспорт логов создаёт JSON.
- [ ] Удаление данных очищает базу, файлы сейфа и crash-отчёты.
- [ ] «Экспорт настроек» создаёт `exports/phoneguard_settings_*.txt`; в файле нет `pin_code_hash`,
      `last_known_imsi` и `lost_mode_active`, а правила блокировки и брандмауэра есть.
- [ ] «Импорт настроек» на другом устройстве возвращает эти правила; количество перенесённых и
      пропущенных строк совпадает с содержимым файла.
- [ ] Импорт файла журналов (JSON) или картинки отклоняется сообщением, настройки не меняются.
- [ ] Подменённый вручную `pin_code_hash` в файле настроек не применяется.
- [ ] Threat intelligence выключен по умолчанию; при включении уходит только имя хоста
      (проверяется через прокси).
- [ ] Ссылка без схемы (`sberbank-online.ru`) и ссылка со схемой в верхнем регистре
      (`HTTPS://Evil.Example/x`) одинаково доходят до проверки — в прокси виден запрос по хосту.
- [ ] Приманки и SMS-команды не мешают друг другу: после `WIPE` каталог приманок очищается.

## 10. Ярлыки и ссылки

- [ ] Долгое нажатие на иконку: ярлыки «Антивор», «Блокировщик», «Брандмауэр», «Сейф» открывают
      соответствующие экраны, а не дашборд.
- [ ] `adb shell am start -a android.intent.action.VIEW -d "phoneguard://settings"` открывает настройки;
      то же для `phonecheck`, `fullscan`, `vault`.
- [ ] Ссылка, открытая при уже запущенном приложении, не создаёт вторую Activity (`singleTop`).

## 11. Фон и обслуживание

- [ ] `ScheduledFullScanWorker` срабатывает по расписанию (и только при включённой настройке).
- [ ] `DataCleanupWorker` удаляет старые записи согласно retention.
- [ ] Уведомление о battery optimization показывается и ведёт в системные настройки.
- [ ] На Xiaomi/Huawei службы не убиваются после добавления в исключения.
- [ ] Сирена не обрывается при выгрузке процесса: включить тревогу, `adb shell am kill com.phoneguard`,
      дождаться — тревога и уведомление «Тревога активна» возвращаются сами.
- [ ] Выключение детектора подглядывания из фона действительно отпускает камеру
      (в статусе батареи нет «Camera», сервис не в списке запущенных).

## 12. Защита приложений

- [ ] Дашборд прокручивается до последней карточки на невысоком экране (раньше нижние обрезались).
- [ ] Карточка «Защита приложений» открывает экран, стрелка «назад» возвращает на дашборд.
- [ ] В «Можно добавить» видны банк/мессенджер/почта, но **не** системные приложения.
- [ ] Переключатель добавляет приложение в «Под наблюдением»; повторное открытие экрана сохраняет выбор.
- [ ] Убрать защиту можно тем же переключателем; после удаления приложение снова появляется в предложениях.
- [ ] Приложение с `SYSTEM_ALERT_WINDOW` (например, «пузырьки» мессенджера) видно в «Кто может подглядывать»
      со средним риском; вместе с доступом к уведомлениям — с высоким.
- [ ] Приложения без прав в «Кто может подглядывать» не попадают.
- [ ] Отмеченное защищённое приложение не показывается само себе как угроза.
- [ ] После удаления отмеченного приложения оно остаётся в «Под наблюдением» с именем пакета.
- [ ] Предел списка (25) показывает сообщение, а не молча игнорирует нажатие.
- [ ] «Отозвать право» у находки открывает **нужный** системный экран: оверлей → «Поверх других
      приложений», спецвозможности → список служб, уведомления → «Доступ к уведомлениям»,
      администратор → «Администраторы устройства».
- [ ] «Больше не предупреждать» убирает строку из находок, но приложение остаётся в «Можно
      добавить» (скрытие — про шум, а не про безопасность).
- [ ] «Опасный сосед» после установки: уведомление приходит в течение минуты, тап открывает
      экран защиты, повторная установка того же пакета в тот же час второго уведомления не даёт.

## 13. Проверки через adb

Всё, что ниже, не проверяется юнит-тестами: нужен настоящий APK, устройство или второй телефон.

### 13.1. Релизный APK: подпись, mapping, 16 КБ

```bash
./build_release.sh production release          # APK + AAB, проверки R8 внутри
APK=app/build/outputs/apk/production/release/*.apk

# 16 КБ страницы памяти (требование Play для targetSdk 35): все несжатые .so выровнены.
$ANDROID_HOME/build-tools/35.0.0/zipalign -c -P 16 -v 4 $APK | tail -5

# Подпись: не «unsigned», схема v2/v3 присутствует.
$ANDROID_HOME/build-tools/35.0.0/apksigner verify --print-certs $APK

# mapping.txt рядом с APK: без него стек-трейс релиза не разобрать.
ls -l app/build/outputs/mapping/productionRelease/mapping.txt
python3 tools/proguard_check.py --mapping app/build/outputs/mapping/productionRelease/mapping.txt
```

- [ ] `zipalign -c -P 16` завершился успешно (на экране нет `BAD`).
- [ ] `apksigner verify` подтверждает подпись, отпечаток совпадает с ключом публикации.
- [ ] `mapping.txt` существует и проверка R8 по нему зелёная.
- [ ] Установка релиза поверх debug падает с `INSTALL_FAILED_UPDATE_INCOMPATIBLE` (разные
      подписи) — это ожидаемо; чистая установка проходит: `adb install -r $APK`.

### 13.2. Перенос сейфа между устройствами

```bash
adb shell pm list packages | grep phoneguard          # com.phoneguard (+ .debug/.staging)
adb pull /sdcard/Android/data/com.phoneguard/files/exports/  # архивы *.pgvault
adb -s <второй-телефон> push phoneguard_vault_XXX.pgvault /sdcard/Download/
```

- [ ] Архив с первого устройства импортируется на втором: элементы, имена, размеры, категории.
- [ ] `strings` по архиву не находит читаемых имён файлов (шифрование, а не переименование).
- [ ] Неверная парольная фраза: понятное сообщение, в сейфе пусто, недописанных файлов нет.
- [ ] Очистка данных перед импортом (`adb shell pm clear com.phoneguard`) не мешает импорту.

### 13.3. Жалоба в BNetzA

```bash
adb logcat -c
adb logcat -s Bnetza:V BnetzaComplaint:V          # в другом окне
```

- [ ] После блокировки спам-звонка доступна кнопка жалобы; нажатие открывает почтовый клиент
      с заполненными получателем, темой и телом (номер маскирован, время и причина на месте).
- [ ] Если почтового клиента нет — приложение не падает и предлагает скопировать текст.
- [ ] В логе нет полного номера: только маска (`+49170123••••`) и хеш/последние 4 цифры.

### 13.4. Разрешения и ослабленная защита

```bash
adb shell pm revoke com.phoneguard android.permission.CAMERA
adb shell pm revoke com.phoneguard android.permission.POST_NOTIFICATIONS
adb shell cmd appops get com.phoneguard CAMERA        # текущее состояние
adb logcat -s PhoneGuardEvents:V
```

- [ ] После отзыва `CAMERA` дашборд показывает карточку «защита не полностью» с кнопкой
      «Разрешить» (или «Открыть настройки», если диалог больше не появится).
- [ ] Нажатие «Разрешить» показывает системный диалог **один раз**; после отказа кнопка меняется
      на «Открыть настройки» и ведёт на экран приложения, а не в пустоту.
- [ ] Уведомления выключены в системе при выданном разрешении: карточка предлагает настройки
      уведомлений, а не диалог.

### 13.5. Опасный сосед после установки

```bash
adb install -r app/build/outputs/apk/production/debug/*.apk      # сам PhoneGuard
adb install -r /path/to/test-overlay.apk                          # тестовое приложение с правом оверлея
adb shell cmd appops set <пакет> SYSTEM_ALERT_WINDOW allow
adb shell dumpsys notification --noredact | grep -i phoneguard
```

- [ ] Уведомление «опасный сосед» приходит в течение минуты после установки.
- [ ] Тап открывает экран «Защита приложений» (`phoneguard://protect`).
- [ ] Повторная установка того же пакета в тот же час второго уведомления не даёт.
